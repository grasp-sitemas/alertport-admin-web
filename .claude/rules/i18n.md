# i18n — next-intl sem routing, 5 locales

## Setup

- **Biblioteca**: `next-intl` v4.
- **Sem routing por URL** — nunca `/pt/...`, `/en/...`. Locale vive em `localStorage['alertport_locale']`.
- **5 idiomas**: `pt` (canônica) · `en` · `es` · `ja` · `zh`.
- **Fallback**: `pt` quando locale for inválido/ausente.
- Arquivos JSON em `src/messages/{pt,en,es,ja,zh}.json`.

## Regra de ouro

**Adicionar ou renomear uma chave = editar os 5 arquivos.** pt recebe o texto canônico; os demais recebem a tradução (ou placeholder `[TODO:<locale>]` se a tradução final ainda vier depois).

Use `/i18n-add <namespace.key> "<texto pt>"` — o command propaga para os 5.

## Estrutura de chaves

Organizada por domínio (não plana). Namespaces:
`common` · `auth` · `sidebar` · `dashboard` · `alerts` · `attendance` · `users` · `collaborators` · `equipment` · `company` · `roles` · `validation` · `table` · `notifications`.

## Uso

```tsx
import { useTranslations } from 'next-intl';

const t = useTranslations('users');
return <h1>{t('title')}</h1>;
```

## ICU

Plurais e datas via ICU:

```json
{ "count": "{count, plural, =0 {Nenhum item} one {1 item} other {# itens}}" }
```

## Troca de idioma

`LocaleSwitcher` salva em `localStorage` e faz `window.location.reload()` para re-bootstrap limpo (evita providers com contexto stale).

## Pitfalls

- Chave ausente em um locale → UI mostra `users.title` literal.
- Hardcode de string em JSX → passa em dev mas quebra locale switcher. Sempre via `t(...)`.
- Alterar valor de `pt` sem atualizar demais → drift silencioso.

## Verificação

- `/i18n-add` garante paridade.
- Agente `i18n-sync` escaneia e reporta ausentes.
- `/pr-ready` inclui check de paridade.
